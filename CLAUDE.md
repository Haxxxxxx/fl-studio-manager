# Hivo (formerly FL Manager)

**Hard rules first: [docs/GUARDRAILS.md](docs/GUARDRAILS.md).** Read them before any work. If a request conflicts with one, stop and say which guardrail before continuing.

Desktop app (Tauri 2 + Rust backend, React 19 + TS + Zustand + Tailwind frontend) that reads FL Studio project folders for a five-person rap crew. Product vision, phases and principles: **[docs/ROADMAP.md](docs/ROADMAP.md)**. Read it before planning features.

## Where we are
- Phase 0 (stabilize + demo-ready) is nearly done. The remaining items are the crew pitch and scrubbing git history before the repo can go public.
- **Launch Kit** (Phase 1b) first slice is in: `src/lib/launchKit.ts` (generate, verify, export files), `src-tauri/src/audio.rs` (mixdown analysis and snippet clips), `src/components/LaunchKitView.tsx`. The kit is regenerated from the project every time; the workspace stores only user edits (`SongMeta.launchKit`).
- **AI layer:** Gemini API free tier (no Firebase project exists for this app). `src-tauri/src/ai.rs` holds the key (`ai.json` in the config dir, or the `GEMINI_API_KEY` env var) and makes one generic structured call (`generateContent` + `responseSchema`). `src/lib/ai.ts` holds the prompts: `draftCopy` (captions + cover concept) and `reviewKit` (a verdict, confidence and suggestion for every field). `sanitizeReview` drops suggestions for measured fields (bpm, duration) and malformed values; never trust raw model output. The AI is optional: everything works without a key.
- **Shorts** (free, local): `src/lib/shorts.ts` draws the 1080×1920 still layer on a canvas (generative art, title, artist, release pill), so ffmpeg needs no fonts. `src-tauri/src/shorts.rs` finds ffmpeg (setting, `FFMPEG_PATH`, PATH, Homebrew/WinGet folders), picks an H.264 encoder, and overlays a `showwaves` waveform plus the snippet audio. `WAVE_*` constants must match in both files. Keep `draw=full` on showwaves: the default makes the strokes about 6% opaque.
- The user wants a **fully free** stack: Gemini free tier for text, local ffmpeg for video, Cloudflare Workers AI (FLUX) for cover concepts. Don't add paid APIs without asking.

- **Cover concepts:** FLUX.1 [schnell] on Cloudflare Workers AI (free 10k neurons/day). `src-tauri/src/cover.rs` holds the account ID + token (`cover.json` in the config dir, or `CLOUDFLARE_ACCOUNT_ID` + `CLOUDFLARE_API_TOKEN`), calls the model and saves `cover-concept.jpg` into the kit folder. `src/lib/cover.ts` turns the cover brief into a prompt: square, no text, no real likeness, no title or names. `src/components/CoverConcepts.tsx` is the 2x2 picker. Images stay in memory. The workspace stores only the pick's seed, prompt and saved path (`LaunchKitMeta.cover`).
- **Phase 1a (local part):** stages are the roadmap lifecycle (`creation → production → prep → release → promotion`, workspace v2; `migrateWorkspace` in `src/lib/songs.ts` maps the old ids and keeps `legacyStatus`). "Finished" = `isFinished()` = Prep or later. `src/lib/calendar.ts` + `CalendarView` = release calendar (dated releases + Launch Kit dates, with readiness checks). `src/lib/crew.ts` + `CrewCards` = next release, stalled tracks (21+ days without a save in Creation/Production), who's on what.
- **Crew backend (Phase 1a, shared part):** Supabase in the EU (eu-west-1), design in [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Only metadata is shared (title or `SongMeta.shareTitle`, stage, key, bpm, tags, credits, dates, has_mixdown, kit_accepted, last_saved_at), never audio, paths, samples, notes or track names. AI calls are separate and disclosed by `aiDisclosure()` in `src/lib/ai.ts`: no raw track names ever, notes only with `Settings.aiIncludeNotes` and only in "Check kit" (drafts feed the FLUX prompt, so they never see notes). Schema + RLS + security-definer functions in `supabase/migrations/`, pgTAP tests in `supabase/tests/database/` (`supabase test db`). Desktop: `src/lib/supabase.ts` (client is null without `VITE_SUPABASE_URL`/`VITE_SUPABASE_ANON_KEY`), `src/lib/crewSync.ts` (pure payload/merge helpers), `src/store/useCrewStore.ts` (debounced push, realtime pull, never syncs demo data), `CrewPanel` / `CrewBoard`. A song is deleted remotely only when it was explicitly unshared, never because a scan missed it. Web dashboard: `web/` (static Vite app for Vercel, reuses `src/` pure modules via `@shared`; data goes browser → Supabase, never through Vercel). Only the anon key ever ships in an app.
- **Files view:** `FilesPanel` in the song drawer; `src-tauri/src/files.rs` lists the song's Launch Kit folder.
- **Languages:** the desktop app is in English and French (Settings → Language). Every visible string goes through `dict(en, fr)` / `tr()` from `src/i18n`; rules and glossary in [docs/I18N.md](docs/I18N.md). New UI text must come with its French. Generated kit files and AI prompts don't follow the app language (captions have their own setting). The website (landing, sign-in and crew dashboard) follows the page: /fr, /en, else the browser; dashboard strings in `web/src/dashboardCopy.ts`.
- **Pipelines:** board / list / table render a `PipelineSource` (`src/components/pipeline/shared.tsx`): yours (`mine.tsx`, columns in `workspace.pipeline`, model in `src/lib/pipeline.ts`) or the crew's (`crew.tsx`, `src/lib/crewBoard.ts`, shared with `web/`). Columns always sit on the 5 stages; moving a card to another stage's column changes the stage. Per-view state (view, collapsed, sort, search) per scope in `src/store/usePipelineView.ts`, never in the workspace or on the server.
- **Crew columns** (`supabase/migrations/20261018000000_crew_columns.sql`): `crew_columns` (members read, no direct writes), `songs.column_id` / `board_order`, `set_crew_columns` (owner only, every stage keeps a column), `move_crew_card` (any member; cross-stage moves use the stage version check). A crew with no columns shows one per stage.
- **Crew section of the menu** (`CrewSection`, `CrewViews.tsx`): Crew board and Crew releases for everyone; Members & invites and Crew settings for the owner. Hidden when not in a crew (`useInCrew`, solo mode).
- **Shared releases:** "Share with {crew}" on a release page shares it and its tracks (`shareRelease` in `useCrewStore`; payload in `releasePayloads`: title, type, colour, date, shared track ids). A release row is deleted only when unshared or deleted on this computer (`Workspace.deletedReleaseShares`), never because another computer doesn't know it.
- **Design identity (1c): System 02, "built like a rack unit"**, designed in Claude Design (project fl-Manager, `templates/redesign` + `templates/brand`). Tokens in `src/theme.css` (shared by the desktop app and `web/`): warm-grey surfaces (`chassis`/`panel`/`raised`), ink (`cream`/`body`/`engrave`), signal (`hot`/`ok`/`warn`/`missing`), Barlow Condensed + IBM Plex Sans/Mono (bundled via @fontsource, never Google Fonts: the CSPs block it), 4px corners. Orange only for the main action and "needs you"; selection is cream on black; status is an LED (`StatusDot`), never a tinted pill; stages are one blue ramp, so charts stay neutral. Conventions for the design agent: `.design-sync/conventions.md`.
- **Digger** (approved exception to guardrails 1-2, see `docs/GUARDRAILS.md`): `Settings.beatFolders` (picked in `settings.rs`, checked by `Scope::beat`), `src-tauri/src/beats.rs` lists mp3/wav/ogg/flac, `src/store/useDigger.ts` (max 5 picks), `DiggerView` + `DigPanel`. Beats never appear in Library, stats or crew. No downloading, links only.
- Not built yet: group vs personal stats, stems, distributor-specific export formats.

- **Multi-DAW:** projects from FL Studio, Ableton Live, REAPER, Studio One, Pro Tools, Cubase and Bitwig are scanned (`src-tauri/src/daws.rs`: detection by extension, per-DAW backup/render/recording folders, readers returning the same `FlpMetadata` shape). Readable: .flp, .als (gzipped XML), .rpp (text), .song (zip, best-effort). Pro Tools/Cubase/Bitwig are closed formats: tracked but nothing read from inside. `ProjectInfo.daw` drives the UI (`src/lib/daws.ts`); render-from-app and packaging are FL-only.

## Commands
- `npm ci && npm run tauri dev`: run the app. Setup per OS: [SETUP.md](SETUP.md).
- `npm run build`: tsc + vite (must stay clean).
- `npm test`: Vitest unit tests for the pure modules in `src/lib` (`*.test.ts`).
- `cd src-tauri && cargo test`: Rust tests.
- `supabase start -x studio,imgproxy,edge-runtime,logflare,vector,supavisor` then `supabase test db`: database tests. Sign-in emails land in Mailpit (http://127.0.0.1:54324).
- `cd web && npm ci && npm run dev`: web dashboard on port 5175.

## Rules
- Developed on Windows and macOS. Crew members use both. `.flp` files store paths with the saving OS's separators (see `native()` in `src-tauri/src/resolve.rs`).
- No hardcoded paths, usernames, real artist names or keys in code, tests or docs. Use placeholders.
- **The webview is untrusted.** Every root, executable and output folder a Rust command uses comes from saved settings via `src-tauri/src/scope.rs` (`Scope::load`), never from IPC arguments; paths a command does receive (a project, a mixdown, a template) are checked against it. Path settings change only through Rust-side pickers/detection in `settings.rs` (`save_settings` ignores path fields). AI calls go through `ai_kit` (typed facts, prompts built in Rust). New commands follow the same rule.
- App data (statuses, releases, people) lives in `workspace.json` in the app config dir, keyed by `.flp` path. Never write to `.flp` files.
- The desktop CSP (`src-tauri/tauri.conf.json` → `security.csp` / `devCsp`) and `web/vercel.json` pin the Supabase project URL. If the project ever changes, update them along with `.env.local`.
